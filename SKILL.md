# Scan Book to Digital PDF

## The conversation should be simple

The user may say only: "Tolong jadikan PDF buku ini buku digital yang nyaman dibaca, mengikuti https://github.com/MuhtajinMukhtar/scan-book-to-digital-pdf." They may provide a PDF as an attachment. Do not require them to know words such as OCR, PP-StructureV3, SHA-256, or command line.

- If no PDF is attached, ask for the PDF.
- Default to a faithful layout and source-like font and paragraph starts. If necessary, ask *one friendly question at a time*, phrased in everyday terms: "Mau huruf seperti buku biasa atau bergaya modern?", "Ukuran tulisan seperti aslinya atau lebih besar?", "Awal paragraf menjorok atau rata kiri?". Offer "biarkan seperti aslinya". Do not ask all questions when defaults suffice.
- Report progress as plain language: pages checked, uncertain pages, pilot/review PDF. Keep technical logs inside work files, not in the user's chat.
- Show a sample PDF first, then ask **"Sudah cocok, atau ingin ada yang diperbaiki?"**. Do not bombard users with font terminology.
- Do not make the user manually choose the OCR engine. On a compatible Mac, use both engines below.

## Source protection and preferences

Record page count, original SHA-256, file metadata and output destination. Never overwrite the original or an approved prior version. **This project requires exact one-to-one physical-page preservation**: source page N must remain output page N, with no paragraphs shifted to neighboring pages, unless the user explicitly changes the contract. A sample approval does NOT waive this requirement. Respect explicit preferences: body serif (Georgia if installed and licensed, else open serif) or sans-serif; source-estimated or specified font size; first-line indent as source / yes / no. Preserve source headings, italics, photos, diagrams, tables, logos, quotes, forms, footers and reading order. Never redistribute copyrighted scans or font files.

## Approval-gated representative pilot (mandatory before a full book)

**Never begin all-page OCR, full-book typesetting, or full-book conversion before explicit approval of the actual pilot PDF.** A request to digitize the book permits source preflight and a limited pilot; it is not approval to process the entire book. Read `references/pilot-and-style-lock.md` for selection criteria, type rules, artifact names, and approval record.

1. Survey all source pages lightly (page thumbnails and page types only, without full-book OCR) to identify representative layouts. Choose **5–8 nonconsecutive source pages** when possible: ordinary body text from different parts, heading/chapter, quotation, photograph, table/form or multi-column layout when present. Fewer pages for a very short book; add up to 10 if needed for a critical unique layout. Tell the user simply: "Saya buat contoh beberapa halaman dulu."
2. Run **Apple Vision + PaddleOCR** only on the selected source pages. Use `scripts/mac_hybrid_ocr.py BOOK.pdf --work-dir ./work --start-page N --end-page N` once per selected page/range; reuse the cache. Compare raw OCR from both engines and verify uncertain text against the image. Run `--compare-only` after collecting selected pages to consolidate the OCR review summary.
3. Infer a source-faithful **typography style profile** from those scans. Fix a consistent body font family and size, justified-last-line-left behavior, leading, line gaps, paragraph spacing and first-line indentation, plus separate consistent styles for chapter headings, captions, quotations, forms and footers. Approximate an unavailable scan font with a licensed local font, not a random font on each page. Respect explicit user choices over source inference. Save `work/pilot/style-profile.json`.
4. **Critical distinction:** OCR text layered invisibly on a scanned page is *not* a retypeset digital pilot. A comparison showing the same source scan on both sides is a preflight/recognition check, not an approvable demonstration. Do not ask for approval of a scan-only pilot. **Digitally typeset** each chosen page in an individual source-sized page frame: if text cannot fit without changing the approved style, do not clip it, shrink the font silently, or flow content into the next page; preserve that page as an original searchable scan and request targeted review. Then compare those pages with real text and preserved images, compare each with its original, audit digital text, embedded font families/sizes and layout. Deliver a **small pilot review PDF** (and simple original-scan-vs-genuinely-retypeset-result comparison), **not** a full-book file. The result side must show vector-rendered, selectable body text with visible approved typography; do not place the original page as a full-page bitmap under transparent OCR text and call it reconstructed. The visual style must be coherent across all sample pages, while headings and captions can use their own intentional styles.
5. **Before requesting approval**, run `python scripts/pilot_typeset_gate.py --source BOOK.pdf --pilot Pilot_v1_REVIEW.pdf --source-pages 7,19,43,88,104 --json work/pilot/pilot-typeset-check.json` (replace the example list with actual physical source pages in the same order as the pilot). Require at least 2 genuine typeset content-page examples, not just an all-scan pilot. If the check fails, status must be `PILOT_INCOMPLETE_SCAN_PREVIEW`, and the agent must actually rebuild sample pages. The guard detects scan-dominant pages/invisible OCR, but is **not** proof of visual fidelity: compare content and fonts manually too. Only after a genuine pilot with meaningful digitally typeset body examples may the status become **PILOT_AWAITING_APPROVAL**. Ask only: **"Apakah contoh ini sudah cocok? Mau lanjut semua halaman atau ada yang perlu diperbaiki?"** If edits requested, revise the pilot and seek approval again. Do not treat silence, the original task, or implicit enthusiasm as approval.
6. On explicit approval of the **specific genuinely typeset pilot version**, record that approval and freeze the chosen style profile and version. Then continue the full-book pipeline below, reusing pilot caches/pages. Apply the approved style rules consistently and flag any newly encountered page archetype or font substitution for targeted review.

## Mac-first dual-OCR pipeline (full-book stage after pilot approval)

1. Set up an isolated Mac Python environment using `references/mac-setup.md`. Verify a real Apple Vision and PaddleOCR PP-StructureV3 installation before processing. Use no production systems or global package changes.
2. **Only after approved pilot** run `python scripts/mac_hybrid_ocr.py BOOK.pdf --work-dir ./work`. Reuse the approved pilot's cached OCR, source hash, and locked styles. This invokes `scripts/ocr_book.py` with Apple Vision, then PP-StructureV3 on **the same cached page images**, saves raw Paddle JSON and Markdown, and generates per-page comparison reports at `work/fusion/`.
3. Read the **raw** `overall_ocr_res.rec_texts` from Paddle JSON, not just its Markdown rendering. The successful prototype recovered seven lines omitted by Paddle Markdown on a five-page pilot; never assume Markdown is complete. Check `paddle_raw_not_in_markdown`, `paddle_not_in_apple`, `apple_not_in_paddle`, and spelling/wording variant warnings. All are **review candidates**, not automatically approved corrections.
4. Confirm missing text and disputed names against **the original page image** before applying a correction. Compare both engines line-by-line; neither engine is authoritative by itself. Preserve uncertainty in a page-specific issue ledger. Do not invent text based on context alone.
5. **Hard layout contract:** produce exactly one fixed-sized output page for each original page, in identical order and physical dimensions. Compose the page's verified text entirely *within that page* using the **approved typography profile** and source reading order. No page break may carry a paragraph/sentence/figure to the next page. Never clip, omit or silently shrink text to make it fit. Do not silently introduce new body fonts/sizes for the same role. Preserve original photos/figures. See `references/page-archetypes.md`. If the page cannot safely fit at the approved styling, preserve that *same page* as an original searchable scan fallback, document the exception, and request targeted review. Never move its overflow to page N+1.
6. Create `work/verified_ocr/page_###.json` for each source page from Apple Vision + PaddleOCR raw text **and actual scan inspection**, retaining original `page` and `source_sha256`. Do not simply rename Apple-only cache as verified. Include missing lines found by either OCR engine and source scan. Write one manifest entry for **every** original physical page with `source_page=N`, `output_page=N`, page mode, source hash, any verified OCR exceptions, and evidence that `content_verified`, `images_verified`, `visual_checked`, `page_boundary_verified`, and `reading_order_verified` are true. No skipped or duplicate pages. Use `references/page-fidelity.md` for schema and non-fitting-page policy.
7. **Mandatory fail-closed page QA** before delivering any full book: run `python scripts/page_fidelity_audit.py --source BOOK.pdf --output Digital_REVIEW.pdf --source-ocr-dir work/verified_ocr --manifest manifest.json --json page-fidelity.json`. Require its `status=PASS`, equal counts/sizes, complete 1:1 mapping and verified original text for **every** corresponding page, no unexplained missing/extra words or adjacent-page spill, no out-of-bounds words and fully documented scan-checked OCR exceptions. Also run `scripts/pdf_audit.py` for fonts and structural checks; compare rendered source/output visuals and all figures. Strict page QA is **not** replaceable by a 95% book-level OCR coverage threshold. See `references/page-fidelity.md` and `references/qa-and-handoff.md`.
8. If **any page** fails the gate, fix only that page, switch it to verified searchable-scan fallback, or leave the book clearly marked `QA_PENDING`; never claim fidelity pass or publish it as final. Deliver a review PDF and concise outstanding-page summary. Mark final only after the user accepts the editorial result. Run `scripts/lossless_optimize.py` only on a copy and verify rendering/text parity.

## Operational boundaries

- Do not treat an unqualified `Ya`/`Cocok` given for a scan-only preliminary preview as authorization for full-book typesetting. Ask the user to approve a **new, genuine digital pilot** after correcting the preview. In an existing Work conversation where the scan-only sample was incorrectly approved, seek correction before any full-book continuation.
- Never circumvent the pilot approval gate by executing all-page OCR, typesetting or exporting before explicit user acceptance. If an approval record is absent or stale, stop and present the pilot.
- This is **not** a one-click universal retypesetter: the AI agent must perform editorial reconstruction of complex pages. `mac_hybrid_ocr.py` prepares source comparisons; it does not generate the final book by itself.
- If Paddle cannot run on the Mac, **do not silently continue Apple-only** and pretend the output passed dual-OCR; report the installation problem and offer the user a safe next step.
- If the current ChatGPT Work or Codex environment cannot execute Mac software, say so briefly. Obtain a permitted Mac execution environment instead of fabricating OCR outputs.
- Preserve cache/source identity. Never automatically overwrite existing OCR results from another source. Do not publish private files in the repository.
- Use `--compare-only` to re-evaluate existing caches without re-running OCR.
